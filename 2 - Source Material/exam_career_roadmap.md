# Exam and Career Roadmap: Software, Cloud, AI, Risk, and Long-Term High-Wage Options

## Purpose

This roadmap is designed for a candidate with:

- Software engineering experience
- React / React Native / Node.js background
- Startup CTO / Technical Lead experience
- AWS EC2 exposure
- LLM evaluation experience
- C/C++ and systems fundamentals from 42-style training
- Current need for income stability
- Long-term goal of reaching high wages through skill + exams + market positioning

The assumption in this document is deliberately conservative:

> Current resume hiring probability is around 50%, not 80-90%.  
> Until the profile reaches 80%+ employability, treat yourself as not yet strongly hireable and keep improving proof, credentials, and job targeting.

This does **not** mean you are incapable. It means the market does not yet have enough obvious proof to trust you quickly. Recruiters are not philosophers. They scan, doubt, reject, and go drink coffee like civilization depends on it.

# The Core Strategy

The goal is not to collect certificates.

The goal is to build a profile that becomes easy to hire.

Your strongest future profile is:

> **Software Engineer specializing in AI-powered applications, cloud deployment, and risk/financial technology.**

That gives you three career doors:

1. **Software / Full Stack / Backend / Cloud**
2. **AI Product Engineering**
3. **Risk-Tech / FinTech / Financial Risk**

You should not bet your entire life on one lane until the market gives feedback.

---

# Employability Threshold Model

Use this model to evaluate yourself.

## 50% Employability

This is where you are assumed to be right now.

Signs:

- Resume shows experience, but story is not fully clear.
- GitHub has code, but not enough product-level proof.
- Startup CTO title exists, but recruiter may doubt hands-on depth.
- AWS exposure exists, but not formalized.
- AI interest exists, but not enough deployed AI products.
- Risk/finance interest exists, but no risk credential or project yet.

At this level:

- Apply, but do not expect high conversion.
- Improve public proof aggressively.
- Do not emotionally overreact to rejection. The market is not judging your soul, just your evidence.

## 65% Employability

You reach this after:

- AWS Developer Associate in progress or completed.
- AI Resume Analyzer deployed.
- Resume and LinkedIn cleaned.
- GitHub pinned repos cleaned.
- 1-2 strong READMEs written.
- Clear job target: Full Stack / AI Product / Cloud App Developer.

At this level:

- You should start getting more recruiter calls.
- Apply to 20-50 jobs per week.
- Start direct messaging founders/recruiters.

## 80% Employability

You reach this after:

- AWS Developer Associate completed.
- AI Resume Analyzer deployed and polished.
- One technical-depth project exists, such as C++ HTTP Server.
- One domain project exists, such as Credit Risk Dashboard.
- GitHub looks like a product-builder profile.
- LinkedIn shows weekly proof.
- Resume has 2-3 strong project bullets.
- You can confidently explain architecture, deployment, APIs, database, and AI integration.

At this level:

- You are not merely “applying.”
- You are selling proof.
- You can target ₹8-12 LPA roles much more seriously.
- You can start filtering for better companies instead of begging every job board like a medieval peasant at the castle gate.

## 90% Employability

You reach this after:

- AWS Developer Associate completed.
- FRM Part I in progress or completed.
- AI Resume Analyzer live.
- Credit Risk Dashboard live.
- C++ HTTP Server documented.
- 2-3 technical articles published.
- 500+ targeted applications/messages sent over months.
- Interview practice completed.
- You can answer system design, SQL, React, AWS, and project questions clearly.

At this level:

- Your profile is no longer “unemployed software guy.”
- It becomes “software engineer with AI/cloud/risk specialization.”
- This is where higher-wage jobs become more realistic.

Until you reach 80%, assume the market does not yet trust your profile enough.

That means your work is not only “apply for jobs.”

Your work is to manufacture proof.

|---|---:|

# Phase 1: Weeks 1-8

## Main Goal

Reach 65% employability.

## Primary Exam

AWS Certified Developer - Associate.

## Primary Project

AI Resume Analyzer.

## What to Look For During This Phase

### In job posts

Look for jobs that ask for:

- React
- React Native
- Node.js
- Express.js
- AWS
- REST APIs
- MongoDB
- SQL
- Startup experience
- Full-stack ownership
- AI integration
- LLM APIs
- “Builder” mindset

Avoid roles that demand:

- 5+ years production Next.js if you do not have it
- hardcore MLOps
- PhD-level AI/ML
- senior cloud architect requirements
- pure DevOps on-call roles if you do not want that path

### In your own resume

Look for weak wording like:

- “worked on”
- “helped with”
- “learning”
- “familiar with”
- “basic knowledge”

Replace with proof-based wording:

- “Built”
- “Deployed”
- “Implemented”
- “Designed”
- “Integrated”
- “Optimized”
- “Led”

### In your GitHub

Look for:

- missing README
- no screenshots
- no architecture explanation
- no live demo
- unclear repo names
- tutorial-looking projects

Fix the top 3 repos first. Do not polish all 39 repos like a lunatic archivist.

# Phase 3: Weeks 17-24

## Main Goal

Reach 80-90% employability.

## Primary Exam Decision

Choose one:

1. **FRM Part I**, if risk-tech/finance feels attractive.
2. **AWS Solutions Architect Associate**, if cloud/software traction is better.
3. **PL-300**, if analytics/reporting roles are getting responses.

## Decision Rules

### Choose FRM Part I if:

- You want a more exam-protected profession.
- You like risk, finance, probability, statistics.
- Risk/fintech/insurance job posts interest you.
- You are willing to study for months.
- You can afford the cost.

### Choose AWS Solutions Architect Associate if:

- AWS Developer helped.
- You are getting cloud/backend interviews.
- You want to remain software-first.
- You want higher cloud credibility.

### Choose PL-300 if:

- You need faster analytics credibility.
- Risk/BI roles are responding.
- You want a cheaper/faster bridge into analytics.
